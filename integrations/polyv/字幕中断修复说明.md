# 2026-10-24 字幕进程中断修复

实际错误：bridge.py 的 write_status 在 Windows 上执行临时文件替换时抛出 PermissionError / WinError 5。watch_bridge.py 外层错误处理再次写状态文件，又抛出同一异常，最终接收进程退出。本地数字人服务仍运行，状态文件却停留在旧的 receiving，造成误判。

修复：

- 状态写入增加线程锁、按进程区分临时文件与短暂重试。
- 持久写入失败返回 False，不再终止字幕接收，包括异常处理分支。
- 本地服务监督它启动的字幕子进程，每三秒检查一次；退出后自动重启。
- WebSocket 增加 pong 超时检测；定时重新取得游客会话，避免永远使用旧场次/旧凭据。
- 控制台检测状态时间戳，超过十二秒显示心跳超时。

验证：单元测试模拟持续 PermissionError 和磁盘写入异常，确认接收状态写入不抛出；解除异常后可正常保存。手动停止本服务所属桥接子进程，监督器已启动新进程，聊天登录恢复，并重新收到直播长句。测试后观察新进程累计收到并提交 50 条实时定稿，error 为 null。

全套 Python 测试 24 项通过；骨骼数学校验 5 项通过。原有 PHP 回调保持备用，当前实时入口仍是观看页 WebSocket。
