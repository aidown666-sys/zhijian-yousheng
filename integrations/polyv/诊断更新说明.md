# 字幕链路诊断更新

把诊断更新包内的 **common.php、callback.php、poll.php** 覆盖到：

`/www/wwwroot/document.plvideo.net/polyv/tangjianguo/demo/shishizimu/`

无需覆盖 private/config.php，也不要删除 private/relay-state.php。本包不含密钥。PHP OPcache 若关闭时间戳检查，需要在面板重载 PHP 后生效。

本机诊断页：http://127.0.0.1:8877/diagnostics

本机启动流程也已修正：现在 start.cmd/start-live.cmd 会随本地服务自动带起字幕桥接，并用单实例锁避免重复运行；不再依赖记得额外打开桥接窗口。手动 start-polyv-bridge.cmd 仍可用于排查。

诊断分四段：

1. 保利威到服务器：每次进入回调的请求次数、最后时间、HTTP 状态和校验/过滤结果。JSON 格式损坏的请求可能在记录前就被拒绝，仍需查看服务器 access.log。
2. 服务器到本机：连接是否活跃、已接收、进入动作队列及缺词失败次数。桥接必须运行；start-polyv-bridge.cmd 窗口关闭后会停止。
3. 动作转换：最新字幕、整句检索/逐词拼接、帧数，或缺少哪些词。
4. 输出窗口：模型是否加载成功、是否正在播放、最后播放的字幕序号。已开的旧输出窗口需 Ctrl+R 刷新才能上报心跳，不必重新创建窗口改变采集对象。

回调结果解释：

- source_registered：验签、频道和来源检查通过，已登记 SRT 地址。这不等于已有逐句字幕。
- signature_or_timestamp_rejected：检查开发者密钥、服务器时间和回调签名算法。received_sign_length=64 时应核实账号是否启用了 SHA256，再相应修改 private/config.php 中 callback_hash。
- wrong_channel：不是频道 8662629。
- filtered_non_original_chinese_live_subtitle：不是 Chinese + isOriginal=Y + source=chatRealtimeSrt；界面显示经过截断的这些来源字段，便于核对真实格式。
- unsupported_srt_url：地址与允许的保利威 SRT 主机/频道路径不符，需依据实际回调核实，不应直接放开任意 URL 下载。

如果直播间字幕在变化，而服务器回调次数一直为 0，应让保利威确认“字幕生成回调”是否仅在字幕文件生成/直播结束时触发。公开文档返回的是 srtUrl，没有逐句文本协议；不能靠修改本机渲染解决没有上游字幕的问题。收到 SRT 后，首次读取只建立历史基线，后续新增时间段才会转发。

服务器排查：查看 Nginx/Apache access.log，搜索 `/polyv/tangjianguo/demo/shishizimu/callback.php`。HTTP 403 是签名或频道被拒绝，400 是 JSON/字幕地址不符，500 是配置/权限等服务器错误；200 仍可能是明确过滤，需结合诊断结果看。不要公开粘贴带 sign/timestamp 的完整请求 URL、Authorization 或 private/config.php。

排查时应分别看“收到、转换、播放”。当前词库只有 1,337 个词，体育比赛等专业词很可能缺失；未收录的完整句子会尝试逐词拼接，但缺词时不会制造替代动作。即使拼接成功，也尚未完成标准手语语法转换。
